1. Prove them wrong.

A large part of my work is researched, planned, structured, and built with **GSD Core**. It turns my 3AM ADHD idea tornado into specifications, executable phases, verified implementations, and—against all statistical expectations—shipped software.

Without GSD, many of my projects would probably still live in a folder named:

```text
final-project-v2-new-FINAL-this-one-really
```

GSD gives my work structure without killing the creative chaos that started it. It helps me turn ambitious ideas into maintainable systems instead of an impressive collection of half-finished experiments.

My personal interpretation of the workflow:

```text
💡 Get idea
🔍 Research everything
📝 Create a suspiciously detailed plan
💻 Build at 3AM
🧪 Discover an edge case nobody asked for
🔧 Fix it anyway
🚀 Ship
🌍 Change country
🔁 Repeat
```

Or, more accurately:

> **Git. Get distracted. Return at 3AM. Ship. Somehow Done.**

Seriously: thank you, **[open-gsd](https://github.com/open-gsd)**, for building the framework behind much of what I build. 🫶

Most of my SaaS work lives in private repositories because these are private solutions—not public open-source projects.

### 🤖 AI-native developer tools

I build MCP servers, model profiles, context-engineering experiments, and agent workflows connecting AI models to useful systems.

Asking an AI to write a poem is fun. Asking it to diagnose your infrastructure at 3AM is a lifestyle.

### 🏠 Self-hosted infrastructure

I enjoy building deployment automation, diagnostics, lifecycle management, and safer operational tooling.

I want infrastructure that gives you control without requiring a ceremonial sacrifice to the DevOps gods. 🔥

### 🪄 CLI experiences

I like installers that install, uninstallers that actually uninstall, and error messages that explain what happened.

“Something went wrong” is not an error message. It is a cry for help.

## 🧭 My highly scientific engineering philosophy

> Make the difficult thing understandable.  
> Make the repeated thing automatic.  
> Make the dangerous thing explicit.  
> Make the error message useful.  
> Add confirmation before deleting production.  
> Then add another confirmation because Kevin will still click it.

I like software that:

- Installs without requiring an ancient Stack Overflow answer
- Explains what went wrong
- Can be removed without an archaeological expedition
- Does not treat the user like an unannounced beta tester
- Survives the journey from “works on my machine” to “works outside my timezone”
